# Codex CLI 실전 노트

결론: 주 세션은 대화형 `codex`로, 리뷰·점검처럼 독립된 일은 `codex exec`를 별도 터미널에서 읽기 전용으로 돌린다. 아래는 0.16x 버전을 직접 써 보고 확인한 내용이다. 옵션은 버전마다 다를 수 있으니 처음에 `codex exec --help`로 확인한다.

## 처음 5분

- `/status`: 모델, 권한, 컨텍스트 사용량을 본다. 세션마다 다시 본다.
- `/model`: 환경이 권장한 모델로 고른다. 목록에 보여도 제한된 모델은 고르지 않는다.
- `/permissions`: 작업 폴더 쓰기를 기본으로 둔다. 전체 권한은 정말 막혔을 때만.
- 업데이트 안내가 떠도 제공된 버전을 바꾸지 않는다.
- `date`로 시간대를 확인한다. 클라우드 환경은 UTC가 흔하다.

## codex exec 옵션 (0.16x에서 확인)

| 옵션 | 쓰는 곳 |
|---|---|
| `-s read-only` | 리뷰어·점검. 파일 쓰기가 실제로 막힌다 |
| `-s workspace-write` | 작업 폴더 안에서 쓰기 |
| `-s danger-full-access` | 쓰지 않는 것을 기본으로 |
| `-m <모델>` | 하위 실행도 모델을 명시한다. 기본값에 맡기지 않는다 |
| `-C <폴더>`, `--add-dir` | 볼 범위 지정 |
| `--json` | 이벤트를 JSONL로 남긴다. 기록이자 결과 추출원 |
| `-c key=value` | 그 실행만 설정 덮어쓰기 |
| `-i <이미지>` | 이미지 첨부 |
| `--skip-git-repo-check` | git이 아닌 폴더에서 실행 |

## 함정

- `codex exec`는 표준 입력을 기다릴 수 있다. 백그라운드·병렬 실행에는 `< /dev/null`을 붙인다.
- `--json` 이벤트에서 답은 `item.completed`의 `agent_message`에 있다. 버전에 따라 필드 이름이 달라서 `kit/scripts/lastmsg.py`는 두 형식을 모두 읽는다.
- 하위 에이전트는 부모 권한을 물려받는다. 프롬프트에 "읽기 전용"이라고 쓰는 것만으로는 막히지 않는다. 강제가 필요하면 `codex exec -s read-only`로 따로 띄운다.
- 읽기 전용 리뷰어도 읽기 명령과 테스트 실행은 한다. 실제로 결함을 실행으로 재현해서 보고한다.
- 4관점 리뷰를 병렬로 돌리면 약 3분이 걸렸다(작은 레포 기준). 관점 수만큼 토큰을 쓴다.

## 컨텍스트

- 큰 파일 탐색은 하위 에이전트나 `codex exec`에 맡기고 요약만 받는다.
- 사용량이 70~80%면 `/compact`나 새 세션. 상태는 PLAN.md·DECISIONS.md에 있으니 "두 파일을 읽고 이어서"로 복구한다.
- 출력을 짧게 요청한다: "결과와 실패한 줄만".

## 위임 문구의 뼈대

- 원본 경로, 질문, 산출물 형식, 마감, 금지 행동을 준다.
- 예: "src/에서 이 조건을 담당하는 함수와 기존 테스트를 찾아줘. 파일은 고치지 마. 위치와 근거만 5줄 이내로."
